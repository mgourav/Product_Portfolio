# Build Checklist

A rolling plan for building this out. Update it as you go — a stale checklist is worse than none.

## Phase 1 — Foundation (this week)
- [x] Repo structure, root README, project template
- [ ] Fill in LinkedIn/contact links in README.md
- [ ] Write your bio in your own voice — the current draft is a starting point, not final copy
- [ ] Set repo description and topics on GitHub (Settings → About)

## Phase 2 — First real project (next 1-2 weeks)
- [ ] Pick ONE problem you can actually ship something small against this week — not a 3-month plan
- [ ] Talk to at least one real person about the problem before building (even informally)
- [ ] Ship a v1, however small — a rubric, a one-page tool, a scoring sheet
- [ ] Fill out the full project README (Problem/Solution/Tradeoffs/Learned) honestly, including what you'd do differently

## Phase 3 — Momentum (ongoing)
- [ ] Commit something — even documentation — at least once a week. A dormant repo reads worse than no repo.
- [ ] Add a second project once the first is genuinely done, not before
- [ ] Ask 2-3 people outside your immediate network to look at the repo and tell you what's unclear
- [ ] Revisit and prune — cut anything that doesn't support "security/identity PM who ships," including this checklist's unused sections

## Notes
- One flagship project that solves a real problem beats several shallow ones.
- Recent activity reads better than total volume — a repo that's been quiet for months is a worse signal than a smaller, active one.
- You're not trying to prove you can write code. You're trying to show how you think about a problem, what you chose not to do, and why.
